Field notes · Build log

We gave Claude Code a research layer. Here is exactly how.

A step-by-step, reproducible walkthrough of how Jax at TheZaraAI installed and validated Agent Reach for Claude Code — plus the guardrails we put around it before a single record touches an outreach campaign.

Jump to quick start Agent Reach on GitHub
Stack Claude Code · Python 3 · npx Time ~10 minutes Cost No paid API keys required

TL;DR

Agent Reach is a scaffolding CLI that installs and wires up the upstream tools an AI agent needs to read the open web — then tells you what works with one diagnostic command (Panniantong/Agent-Reach).

It is research infrastructure. It does not produce qualified leads, and this guide does not treat it as if it does.

→ Five commands. One doctor check. Then the boring, important part: scope, validation, and human review.

Agent Reach is third-party open-source software we use internally. It is not a TheZaraAI product, sub-brand, or separate company.

01 / Context

Why we added a research layer

TheZaraAI runs an AI-assisted lead-generation workflow. The weakest link was never the sending infrastructure — it was the research in front of it.

The problem

Research on local HVAC and construction firms was manual, inconsistent, and slow. Every prospect list arrived with different fields, different freshness, and no traceable source.

The hypothesis

If the agent can read public sources directly — the open web, RSS, GitHub, YouTube transcripts — research becomes repeatable and citable instead of ad hoc.

The honest scope

Better inputs, not automatic outcomes. Nothing here shortens the work of defining an ICP, validating data, or reviewing a message before it ships.

How this fits TheZaraAI

Agent Reach is internal research infrastructure, not something we sell, rebrand, or spin out. The commercial offer stays exactly where it is — under TheZaraAI — with HVAC and selected construction firms as the initial vertical. There is no separate product name, no DBA, and no new entity behind this work.

What this is not

Agent Reach does not generate qualified leads, book meetings, or produce revenue on its own. It is a read layer. Everything downstream — ICP definition, data validation, compliant enrichment, message quality, and human review — is still your job.

02 / Quick start

The whole install, in one block

Copy, paste, run in order. Each command is explained in the next section. Run these from your normal terminal, not from inside a Claude Code session.

bash · verified sequence 
# 1. Add the Agent Reach skill (choose Claude Code at the prompt)
npx skills add Panniantong/Agent-Reach@agent-reach

# 2. Install the CLI from source
python3 -m pip install "https://github.com/Panniantong/agent-reach/archive/main.zip"

# 3. Detect the environment and install the upstream tools
agent-reach install --env=auto

# 4. Validate every channel
agent-reach doctor

# 5. Restart / open Claude Code so it picks up the new skill
claude

Prerequisites: Node.js (for npx), Python 3 with pip, Git, and Claude Code already installed and authenticated.

03 / Walkthrough

Step by step, with what to expect

This is the exact sequence Jax ran. Nothing has been reordered or cleaned up after the fact.

  1. STEP 01

    Add the skill

    The skill installer registers Agent Reach's SKILL.md in your agent's skills directory so the agent knows which upstream tool to reach for.

    bash
    npx skills add Panniantong/Agent-Reach@agent-reach

    At the prompt, select Claude Code. Select Codex only if you actually use it — every extra target is another config surface you have to maintain and audit. We selected Claude Code only.

  2. STEP 02

    Install the CLI

    The skill files alone do not give you the agent-reach command. Install the Python package from the repository archive:

    bash
    python3 -m pip install "https://github.com/Panniantong/agent-reach/archive/main.zip"

    Keep the quotes — some shells will otherwise choke on the URL. If your system Python is managed and blocks installs, see Troubleshooting for the virtual-environment route.

  3. STEP 03

    Run the installer

    bash
    agent-reach install --env=auto

    --env=auto detects whether you are on a local machine or a server and installs the upstream dependencies accordingly — Node tooling, the GitHub CLI, transcript tooling, an MCP-based search connector, and the channel adapters (project README).

    Read the output before you accept it. This step installs software on your machine. On a shared box or a production server, prefer the project's safer variants: --dry-run to preview, or --safe for a restricted install.

  4. STEP 04

    Validate with doctor

    This is the step most people skip and then debug for an hour. doctor reports, channel by channel, what is ready, what is missing, and how to fix it.

    bash
    agent-reach doctor

    Treat the output as your acceptance test. We only marked the install "done" once the channels we intended to use reported healthy — and we deliberately left the authenticated, cookie-based channels unconfigured. See Safe use.

  5. STEP 05

    Restart Claude Code

    A running session will not see a skill that was registered after it started. Quit the session, then open a new one:

    bash
    claude

    Then confirm it landed with a small, low-stakes request — fetch a public page, pull an RSS feed, or read a public GitHub repository — before you point it at anything that matters.

04 / Architecture

Where the research layer actually sits

Agent Reach occupies exactly one box in this diagram. The boxes on either side of it are where the quality comes from.

  1. Stage 01Public sourcesOpen web pages, RSS/Atom feeds, public GitHub repositories, YouTube transcripts, platform-approved APIs.
  2. Stage 02Agent Reach researchThe agent reads and summarises those sources on request, with the source URL kept alongside every claim.
  3. Stage 03Validation & enrichmentDeduplicate, verify against a second source, confirm the record is current, enrich only through compliant, licensed providers.
  4. Stage 04CRM / InstantlyOnly validated records enter the system of record, each carrying its source and the date it was captured.
  5. Stage 05Personalised outreachHuman-reviewed messaging grounded in a verifiable, public fact — with suppression lists and opt-out honoured before send.
  6. Stage 06MeasurementReply quality, meetings booked, and complaint rate. Research quality is judged by outcomes, not by volume collected.
The rule we hold ourselves to

No record moves from Stage 02 to Stage 04 without a source URL, a validation check, and a named human who reviewed it. A research layer that lets you skip those steps is not a speed-up — it is a liability generator.

05 / Worked example

HVAC and construction firms, end to end

HVAC and selected construction firms are TheZaraAI's initial vertical, and this is the primary use case for the research layer — so it is worth showing in full. Everything below runs on publicly available information and platform-approved APIs. Agent Reach does the reading in stages 1 and 2 only — it does not access logged-in social accounts, and it does not produce a qualified lead on its own.

Sample ICP filters

Write these down before you research anything. An undefined ICP turns a research layer into a list generator.

Where the data legitimately comes from

Google Business Profile

Publicly listed firm name, category, address, service area, hours, rating, and website — read from public listing pages or, where you need it at volume, through the official Places API under its terms and your own key.

Company websites

Services offered, service-area pages, brands installed, team and "about" pages, careers pages, financing options, and stated response times. The richest and least ambiguous source.

Public directories & associations

Public business directory listings, BBB profiles, and trade-body member directories such as ACCA, PHCC, NAHB, or NARI. Read the public page; do not create accounts to get behind a gate.

Permit & licensing records

State contractor and mechanical licence boards, and municipal or county permit portals — where the data is published for public access and the terms allow automated reading. Check the portal's terms and rate limits first; some require a formal records request instead.

Public social & business pages

Only pages a signed-out visitor can see: a public company page, a public job post, a public YouTube channel and its transcripts. No logged-in sessions, no cookie reuse, no gated profile data.

Approved data providers

For contact-level detail: licensed B2B data and email-verification vendors with a documented lawful basis and a contract. This is enrichment, not collection — and it happens after the firm already passed the ICP filter.

The compliant workflow

  1. STAGE 01

    Discover firms in the service area

    Ask the agent for HVAC and construction firms operating in the target ZIP clusters, and require a source URL for every row. Output is a raw candidate list — nothing more.

    example brief to the agent
    # Paste into Claude Code after the install is validated
Build a candidate list of independent HVAC and residential construction
firms serving ZIP codes 27601, 27604, 27609, 27612.

Use only publicly accessible sources: public business listings, company
websites, public trade-association directories, and public licence or
permit records where the site's terms allow automated reading.
Do not use logged-in sessions, cookies, or gated profile data.

For each firm return: legal/trading name, website, city, service area,
services offered, apparent headcount signal, licence number if public,
and the exact source URL for every field. Mark anything you inferred
as "inferred" rather than stating it as fact.
  2. STAGE 02

    Validate the firm and the decision-maker role

    A name on a website is not a validated contact. We require two independent public sources agreeing on both the company and the person's role before the record advances.

    • Company exists and is active: licence board record, business registration or Secretary of State filing, and a live website.
    • Role is real and current: the licence holder or qualifying party named on the public licence record, an "our team" or "about" page, a permit applicant name, or a signed public post from the company page.
    • Still trading: recent reviews, a recent permit, a current job post, or a dated site update within the last 6–12 months.
    • Reject on sight: role that only appears in one unverifiable place, franchise-owned locations, and any record whose source URL no longer resolves.
  3. STAGE 03

    Enrich through approved providers only

    Business contact details come from licensed providers under contract, not from harvesting. Every enriched field carries its provider, the retrieval date, and a lawful basis. Verify deliverability before send, honour suppression and opt-out lists at ingestion, and drop any record the provider cannot substantiate.

  4. STAGE 04

    Segment by service area, size, and signal

    Segmentation is what makes the later message specific. We split on three axes and treat each combination as its own small campaign.

    • Service area: ZIP cluster or drive-time band — it changes the local proof points you can cite.
    • Size band: owner-operator (1–4), small crew (5–15), established (16–50). Each has a different bottleneck and a different buyer.
    • Signal: the specific, dated, public trigger below. No trigger, no personalised angle — the record waits in the nurture segment instead.
  5. STAGE 05

    Route qualified records into Instantly

    Only records that cleared stages 2 and 3, carry a source URL, and passed human review get uploaded. One campaign per segment, custom fields mapped so the personalisation is grounded in the verified fact rather than invented.

    record schema · one row per firm
    company_name, trade, website, city, state, zip, service_area
size_band, licence_number, licence_status, licence_source_url
contact_first_name, contact_role, role_source_url
email, email_verification_status, enrichment_provider, enrichment_date
trigger_signal, trigger_date, trigger_source_url
segment_id, reviewed_by, reviewed_at, suppression_checked

    Then keep sending volume inside your warmed capacity, watch complaint and bounce rates as hard stops, and pull the campaign — not just the record — if either drifts.

Say this out loud before you start

None of this guarantees leads. It produces a defensible, source-linked shortlist of HVAC and construction firms that match a defined ICP. Whether that turns into pipeline depends on the offer, the message, the timing, and the humans reviewing it — not on the research tool.

06 / Safe use

Safe, compliant use — read this before you point it at anything

Agent Reach supports more channels than we use. That is a deliberate choice on our side, not a limitation of the tool. We restrict ourselves to public and platform-approved sources.

What we use it for

  • Public web pages and general web search
  • RSS and Atom feeds
  • Public GitHub repositories, issues, and code search
  • YouTube transcripts of publicly available videos
  • Official, platform-approved APIs and tools, used within their terms and rate limits
  • Published company material: docs, changelogs, pricing pages, job posts, press releases

What we do not do

  • Export browser cookies or reuse session tokens to impersonate a logged-in user
  • Work around login walls, paywalls, or rate limits
  • Bypass or disable any platform control, CAPTCHA, or access restriction
  • Collect from authenticated X, LinkedIn, Instagram, or Reddit sessions
  • Collect personal data beyond what a legitimate business purpose requires
  • Ignore robots.txt, terms of service, or a platform's stated automation policy
Non-negotiables
  • Never commit credentials, cookies, tokens, or API keys to a repository. This guide contains none, and neither should your fork.
  • Respect privacy law — GDPR, CCPA, CAN-SPAM, and local equivalents. Keep a lawful basis, honour deletion and opt-out requests, and keep suppression lists current.
  • Rate-limit yourself. Polite, low-volume reading is both more defensible and less likely to break.
  • Review the tool's own scope before extending it. Enabling a channel is a decision with legal and account consequences, not a config toggle.
07 / Troubleshooting

The four things that actually go wrong

In order of how often we hit them.

agent-reach: command not found

The package installed, but the executable is not on your PATH. Check whether Python can still see it, then add the user script directory to your shell profile:

bash
# Does the module exist even though the shim is missing?
python3 -m agent_reach --help

# Where does pip put user scripts?
python3 -m site --user-base

# macOS / Linux — append to ~/.zshrc or ~/.bashrc
export PATH="$(python3 -m site --user-base)/bin:$PATH"

# Reload the shell config
source ~/.zshrc

On Windows, the equivalent directory is %APPDATA%\Python\Python3x\Scripts. Open a new terminal after changing PATH — the current one will not pick it up.

Python or pip refuses to install

Modern Python distributions mark the system environment as externally managed and block direct installs. Do not force it with --break-system-packages. Use a virtual environment or a user install instead:

bash
# Confirm you are on Python 3.9+ and have pip
python3 --version
python3 -m pip --version

# Option A — isolated virtual environment (recommended)
python3 -m venv ~/.venvs/agent-reach
source ~/.venvs/agent-reach/bin/activate
python3 -m pip install "https://github.com/Panniantong/agent-reach/archive/main.zip"

# Option B — per-user install
python3 -m pip install --user "https://github.com/Panniantong/agent-reach/archive/main.zip"

# If pip itself is stale
python3 -m pip install --upgrade pip

If you use a virtual environment, remember that agent-reach only exists while that environment is active. pipx is a good alternative if you want a globally available command with an isolated environment.

Claude Code does not see the skill

Skills are loaded at session start. A session that was already running when you installed will never see it.

bash
# Fully exit the running session, then start a fresh one
claude

Still missing? Re-run npx skills add Panniantong/Agent-Reach@agent-reach and confirm you selected Claude Code at the prompt — it is easy to skip past that selection. Then check that a skill file for Agent Reach exists in your Claude Code skills directory before debugging anything else.

A channel reports unhealthy in doctor

agent-reach doctor is the source of truth. It names the channel, its status, and the fix.

bash
agent-reach doctor

Work through the report one channel at a time. Most failures are a missing upstream binary — re-running agent-reach install --env=auto resolves them. If a channel requires an authenticated session, leave it unconfigured unless you have an approved, terms-compliant path to that data; a red line in doctor for a channel you deliberately do not use is a correct result, not a failure.
